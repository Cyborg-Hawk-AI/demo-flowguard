# FlowGuard

> Drop-in error layer that catches, logs, and self-heals Make/n8n workflow failures automatically.

## What is FlowGuard?

FlowGuard is built for **Automation consultants and SMB owners running critical business workflows on Make, n8n, or Zapier who cannot afford silent failures**. Wraps existing workflows via webhook — zero migration friction. Clients keep their current tool; FlowGuard just adds a safety net layer.

### Core MVP features
- Webhook-based error interceptor that wraps any existing workflow without code changes
- Categorized failure dashboard: API timeouts, missing fields, rate limits — each with suggested fix
- Auto-retry logic with configurable backoff for transient failures
- Plain-English Slack/email alert explaining what failed and why in non-technical language
- One-click 'freeze and notify' mode that pauses the workflow and alerts the owner instead of silently failing

## How this business runs itself (mailbox money)

The goal is passive, low-maintenance recurring revenue: AI is how we build and operate the business, not necessarily what it sells.

Workflows send errors to FlowGuard's webhook endpoint. A BullMQ worker classifies the error via OpenAI and triggers retries or alerts. Slack/email notifications are sent via API with zero human involvement. Stripe webhooks manage subscription state. A cron job sends a weekly digest of all errors and resolutions. Owner estimated time: 1 hour/week.

**Estimated owner time:** ~1 hour(s)/week

**MVP estimate:** Node.js + Supabase + Resend (email) + Slack API; webhook receiver + retry queue via BullMQ; 3 weeks to MVP
